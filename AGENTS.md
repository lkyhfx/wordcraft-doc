# AGENTS

Guidance for coding agents working in this repository.

## What this is

A Node.js native addon that converts Word documents, published to npm as
`@lkyhfx/wordcraft-doc`: legacy `.doc` → `.docx`, `.doc` → PDF, and `.docx` →
PDF. The conversion itself is done by
[WordCraft](https://github.com/storytold/wordcraft), vendored as a git submodule.

## Layout

| Path | What it is |
|---|---|
| `upstream/wordcraft/` | WordCraft submodule. **Never edit.** |
| `native/` | The Rust binding (its own Cargo workspace root). |
| `native/src/lib.rs` | The whole public surface: six napi functions, error mapping, limits, output verification, the font check. |
| `npm/` | The published package: `index.js` and `index.d.ts` are generated by the napi CLI. |
| `tests/` | `node:test` suites, `fixtures/*.doc`, and the dependency-free `zip.ts` / `pdf.ts` / `docx.ts` helpers. |
| `scripts/` | `build-native.sh`, `package-native.sh`, `test-package.sh`, `sync-upstream.sh`. |
| `.dev/` | Local toolchains and scratch space. **Git-ignored; not part of the project.** |

## Ground rules

1. **Upstream stays pristine.** No edits under `upstream/wordcraft/`. If an
   upstream change is unavoidable, it is a numbered patch in `UPSTREAM.md`.
2. **Own code stays thin.** `native/src/lib.rs` calls
   `wordcraft_docbin::read_with_password`, `wordcraft_docx::read_with_password`,
   `wordcraft_docx::write` and `wordcraft_pdf::export`, and nothing else about
   the formats. No parsing, no OOXML, no document model, no layout, no PDF
   writing. The one exception is `check_fonts`, which asks
   `wordcraft_fonts::FontDb` whether a character can be drawn.
3. **No scope creep.** No GUI, no CLI, no MCP, no editing API, no image/PNG
   export, no LibreOffice, no Word/WPS automation, no background service, and no
   bundled or downloaded fonts. The package converts documents to DOCX and PDF.
4. **No unnecessary upstream components.** `native/Cargo.lock` must not contain
   `wordcraft-engine`, `wordcraft-render`, `wordcraft-ui-egui`, `wordcraft-mcp`,
   `wordcraft-cli`, `wordcraft-zotero`, `wordcraft-formats`, `egui`, `eframe` or
   `rayon`. `sync-upstream.sh` and `package-native.sh` enforce this.
5. **Never publish or commit automatically** after a sync. The scripts stop and
   print what the human should review.

## Commands

```bash
# todo: npm install once (provides the napi CLI into .dev/cli)
./scripts/build-native.sh --target all   # build both targets
npm test                                 # conversion + PDF suites
./scripts/package-native.sh              # three tarballs into npm-dist/
./scripts/test-package.sh                # install + convert + typecheck
./scripts/sync-upstream.sh <tag>         # move the submodule, verify, stage
```

Cross-compiling to arm64 needs an aarch64 linker. `build-native.sh` probes for
one in `.dev/tcx/bin`, `aarch64-linux-gnu-gcc`, then `AARCH64_LINKER`. The built
arm64 addon can be exercised under `qemu-aarch64-static` with the arm64 Node in
`.dev/node-v24.10.0-linux-arm64`.

## Conventions

- Errors reaching JavaScript carry a stable `code` (`ERR_WORDCRAFT_*`). Adding
  an error kind means adding a code, a row in the README table, and a test.
- A new `DocbinError`/`DocxError`/`PdfError` variant upstream will break the
  exhaustive `match` in `native/src/lib.rs`. That is deliberate.
- Tests assert on the produced file — DOCX package validity, text, structures;
  PDF header, page objects, trailer, embedded fonts — never just that the
  promise resolved. `tests/zip.ts` and `tests/pdf.ts` are dependency-free
  readers for that purpose; `tests/docx.ts` builds DOCX inputs a fixture cannot.
- PDF tests that depend on installed fonts must either use the bundled Latin
  coverage or the uncovered `U+10FFFD` sentinel, so they pass with and without a
  system CJK font. Never assert that CJK is *missing*.
- `native/Cargo.toml` repeats upstream's `[patch.crates-io]` for `krilla`. Both
  revs must match upstream's `Cargo.toml`; `sync-upstream.sh` re-pins the patch.
- The environment variables `CARGO_HOME` and `npm_config_cache` may be pointed
  inside `.dev/` when the usual homes are read-only.
