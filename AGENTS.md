# AGENTS

Guidance for coding agents working in this repository.

## What this is

A Node.js native addon that converts legacy Word `.doc` files to `.docx`,
published to npm as `@lkyhfx/wordcraft-doc`. The conversion itself is done by
[WordCraft](https://github.com/storytold/wordcraft), vendored as a git submodule.

## Layout

| Path | What it is |
|---|---|
| `upstream/wordcraft/` | WordCraft submodule. **Never edit.** |
| `native/` | The Rust binding (its own Cargo workspace root). |
| `native/src/lib.rs` | The whole public surface: two napi functions, error mapping, limits. |
| `npm/` | The published package: `index.js` and `index.d.ts` are generated by the napi CLI. |
| `tests/` | `node:test` suites plus `fixtures/*.doc`. |
| `scripts/` | `build-native.sh`, `package-native.sh`, `test-package.sh`, `sync-upstream.sh`. |
| `.dev/` | Local toolchains and scratch space. **Git-ignored; not part of the project.** |

## Ground rules

1. **Upstream stays pristine.** No edits under `upstream/wordcraft/`. If an
   upstream change is unavoidable, it is a numbered patch in `UPSTREAM.md`.
2. **Own code stays thin.** `native/src/lib.rs` calls
   `wordcraft_docbin::read_with_password` and `wordcraft_docx::write` and does
   nothing else about the formats. No parsing, no OOXML, no document model.
3. **No scope creep.** No PDF, no rendering, no GUI, no CLI, no MCP, no
   editing API. The package converts DOC to DOCX.
4. **Never publish or commit automatically** after a sync. The scripts stop and
   print what the human should review.

## Commands

```bash
# todo: npm install once (provides the napi CLI into .dev/cli)
./scripts/build-native.sh --target all   # build both targets
npm test                                 # 41 conversion tests
./scripts/package-native.sh              # three tarballs into npm-dist/
./scripts/test-package.sh                # install + convert + typecheck
./scripts/sync-upstream.sh <tag>         # move the submodule, verify, stage
```

Cross-compiling to arm64 needs an aarch64 linker. `build-native.sh` probes for
one in `.dev/tcx/bin`, `aarch64-linux-gnu-gcc`, then `AARCH64_LINKER`.

## Conventions

- Errors reaching JavaScript carry a stable `code` (`ERR_WORDCRAFT_*`). Adding
  an error kind means adding a code, a row in the README table, and a test.
- A new `DocbinError`/`DocxError` variant upstream will break the exhaustive
  `match` in `native/src/lib.rs`. That is deliberate.
- Tests assert on the produced DOCX (package validity, text, structures), never
  just that the promise resolved. `tests/zip.ts` is a dependency-free reader for
  that purpose.
- The environment variables `CARGO_HOME` and `npm_config_cache` may be pointed
  inside `.dev/` when the usual homes are read-only.
